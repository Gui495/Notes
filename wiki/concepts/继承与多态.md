继承是用 `extends` 在类型之间建立「子类是超类的一种」的关系并复用其成员，多态则是同一个调用点在运行期按对象的实际类型选择实现；两者合起来构成 Java 面向对象可扩展性的骨架。

> 📌 来源性质：本页无 raw 素材，依据外部资料编写，待有 raw 素材时再收编。

## 继承的语义与 extends 的限制

Java 的类继承是单继承：除 `Object` 之外，每个类有且只有一个直接超类，没有写 `extends` 的类隐含继承 `Object`，继承链一路向上最终都落到 `Object`。语言层面之所以拒绝类的多继承，Oracle 教程给出的理由是避免「multiple inheritance of state」——若一个类能继承多个类的字段，实例化时字段归属与初始化顺序会变得无法裁定；接口没有实例字段，所以多重继承的风险被限制在「类型」和「实现」两个层面。这也是为什么 Java 允许多实现接口、却只允许单继承类。

子类继承超类的字段、方法和嵌套类，但**构造器不是成员**，因此不被继承：父类的构造器不会变成子类可调用的构造器，只能在子类构造器里用 `super(...)` 主动调用。成员可见性决定继承范围：`public` 与 `protected` 成员跨包也被继承，包私有成员只对同包子类可见，`private` 成员根本不被继承（子类只能通过父类留下的 public/protected 访问器间接使用）。

`super` 与 `this` 的调用规则是硬性的：调用父类构造器的 `super(...)` 必须是子类构造器的第一条语句；若子类构造器没有显式写 `super(...)` 或 `this(...)`，编译器会自动插入对父类**无参**构造器的调用，此时父类若没有无参构造器就编译失败。构造过程会形成 constructor chaining，一直链到 `Object` 的构造器，所以父类构造器里执行的代码发生在子类字段初始化之前。用 `this(...)` 委托本类另一个构造器时同样受「构造器委托语句必须是首条语句」的约束（JLS §8.8.7 的规则，本页未逐字核对原文，待核）。

```java
class Bicycle { Bicycle(int gear) { /* ... */ } }
class MountainBike extends Bicycle {
    int seatHeight;
    MountainBike(int gear, int h) { super(gear); seatHeight = h; } // super 必须是首句
}
```

字段和方法在继承里走两条不同规则，这是最容易混淆的判据：同名字段是**隐藏**（hiding），访问到哪一个由变量声明类型决定；同签名的实例方法是**重写**，调用到哪一个由对象实际类型决定。父类实现可通过 `super.method()` 显式复用，`super` 绕过了重写选择。

## 方法重写：签名、协变返回与访问权限

重写要求名字相同、参数个数与类型相同（即签名相同），并且返回类型相同或为被重写方法返回类型的**子类型**，后者称为协变返回类型（covariant return type）。`@Override` 不是语法必需，但它让编译器替你验证「确实重写了某个父类方法」：参数表写错时，加注解会直接编译报错，不加注解则静默变成一个重载方法——这是「以为重写了、其实新增了一个方法」的典型来源。

访问权限只能放宽、不能收窄：父类 `protected` 的实例方法，子类可以改成 `public`，不能改成 `private`。实例方法与 `static` 方法不能互换：父类实例方法在子类写成 `static`（或反之）是编译错误；父子各有一个同签名 `static` 方法时是**隐藏**而非重写，调用哪一个取决于你用哪个类（或哪个声明类型）去调用，而不是取决于对象。`final` 方法不能被重写，`final` 类不能被继承（`String` 即如此）；教程还建议构造器中调用到的方法尽量声明 `final`，否则子类重写它时，方法可能在子类字段尚未初始化时就被执行。

接口方法与类的实例方法在这一层是统一的：接口的 `abstract` 方法与 `default` 方法按实例方法继承。多个互不相关的父接口给出同签名 `default` 方法时，编译器报冲突错误，实现类必须显式重写，并可用 `FlyCar.super.startEngine(key)` 这种带直接父接口名的形式选择某个默认实现；类继承来的实例方法优先于接口 `default` 方法；接口里的 `static` 方法从不被继承。`default` 方法本质上是「实现的多继承」，这也是它带来冲突规则的原因。

## 重载与重写的区别

| 判据 | 重载（overload） | 重写（override） |
| --- | --- | --- |
| 发生位置 | 同一个类内，或子类新增同名的不同参数方法 | 子类与超类（含接口实现）之间 |
| 签名要求 | 名字相同，参数个数/类型必须不同 | 名字与参数表必须完全相同 |
| 返回类型 | 不受约束 | 相同或协变子类型 |
| 访问权限 | 不受约束 | 不能比被重写方法更严格 |
| 绑定时机 | 编译期解析（按实参的静态类型选最匹配版本） | 运行期按对象实际类型分派 |
| 注解 | 无 | 建议加 `@Override` |
| static / final / private | 都可参与重载 | 都不参与重写 |

需要特别注意最后一行的反向含义：子类里对继承来的方法写一个**不同参数表**的同名方法，教程明确说这既不是隐藏也不是重写，而是子类独有的新方法。判定「是重写还是重载」只看签名，不看方法体是否相似。

## 多态：运行期分派

多态的判据被 Oracle 教程压缩成一句：JVM 调用的是「变量所引用的那个对象」上的合适方法，而不是「变量类型」所定义的方法，这一行为叫 virtual method invocation。三个条件缺一不可：存在继承或接口实现关系、方法被重写、调用点通过父类型（或接口类型）引用发起且调用的是实例方法。编译期只检查引用类型上有没有这个签名；运行期才决定执行哪份实现，所以「`Animal a = new Cat(); a.sound()` 调的是 Cat 的版本」是规则而不是巧合。

字节码层面，这类调用点使用 `invokevirtual`（类方法）或 `invokeinterface`（接口方法），由它们在运行期完成上述选择；`invokestatic`、`invokespecial`（构造器、`super.`、私有方法）则不参与这种动态选择。常见资料把实现机制称为「虚方法表（vtable）」，但这属于 HotSpot 的实现技术而非规范强制：JVMS 明确把对象内部结构、内存布局和指令优化留给实现者，因此「每个类一张方法表、调用时查表」只能当作对实现的通俗描述，具体到某个 JDK 版本的实现细节待核。

不参与多态的四类成员可以当作排除法使用：`static` 方法（隐藏，编译期按类选择）、`private` 方法（不被继承，编译期绑定）、`final` 方法（不可重写）、构造器（不是可继承的方法）。字段同样不参与多态，只被隐藏。

## 转型：向上与向下

把子类对象赋给父类型变量是隐式向上转型，永远安全，因为它只丢弃了子类特有的接口。反向的向下转型必须显式写 `(SubType)`，编译器会插入运行期类型检查，失败抛 `ClassCastException`——这类错误编译期查不出来，只能靠 `instanceof` 预先判定。

Java 16 起 `instanceof` 支持类型模式，把「判定 + 转型 + 声明变量」合成一步：

```java
if (obj instanceof MountainBike mb && mb.seatHeight > 0) { use(mb); }
```

模式变量采用流敏感作用域（flow scoping）：「在确实匹配成功的地方才在作用域内」。因此 `&&` 右侧可以使用该变量，`||` 右侧不行；若模式类型是表达式静态类型的超类型（该判定恒真），编译器直接报错。版本差异需要记住：该特性在 JDK 14（JEP 305）、JDK 15（JEP 375）是预览，JDK 16 由 JEP 394 定稿，同时取消了模式变量隐式 `final` 的限制。与泛型配合时，向下转型到参数化类型可能只是「未检查转换」，编译期只给警告、运行期才可能暴露堆污染，这一点见 [[泛型]]。

## 抽象类与接口的分工

抽象类用 `abstract` 声明，不能被实例化但可以被继承；它既可以含抽象方法，也可以含带实现的方法、实例字段、构造器以及 `private`/`protected` 成员。含有抽象方法的类必须声明为 `abstract`；子类若不实现全部抽象方法，子类自己也得声明为 `abstract`（「抽象类实现接口但只实现一部分方法」是允许的，缺的部分交给更下层）。接口的字段隐式 `public static final`，未标 `default`/`static` 的方法隐式 `abstract`，`default` 方法隐式 `public`；一个类只能 `extends` 一个类，但可以 `implements` 任意多个接口。

选择判据可以直接引用教程的三条对照：需要在若干**紧密相关**的类之间共享代码、需要非 `public` 的成员、需要可变的实例字段，用抽象类；希望**互不相关**的类共享同一个类型、只约定行为不关心实现者、需要多重类型，用接口。JDK 自身的 `AbstractMap` 与 `Map` 是两条路线并用的样本：`HashMap` 既实现多个接口，又继承抽象类。`default` 方法存在的现实动机是接口演化——给 `Map` 增加 `forEach`、`merge` 不必让所有既有实现类改代码；代价就是把实现的冲突规则引了进来。

## 易错点

把「隐藏」误当「重写」是最常见的一类：字段同名、`static` 方法同名都只看声明类型，改 `new` 出来的对象并不会改变结果。第二类是重写时收窄访问权限，编译即失败。第三类是在构造器里调用可被重写的方法，子类版本会在子类字段初始化完成之前执行，教程因此建议把这类方法设为 `final`。第四类是依赖向下转型而不先判定，`ClassCastException` 只在运行期出现。
