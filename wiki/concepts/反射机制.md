反射（Reflection）是 Java 在**运行期**观察并修改类与对象的能力：程序可以在此刻拿到任意一个类的完整结构（成员变量、方法、构造方法），并据此创建对象、读写字段、调用方法，而不必在编译期就知道是哪个类。

它成立的前提是 JVM 为每个已加载的类保留了一份描述自身结构的信息，反射就是用 `Class` 对象去读这份信息。因此反射的第一动作永远是「拿到 `Class` 对象」，三条路：`对象.getClass()`、`类名.class`、`Class.forName("全限定名")`。

**四类能力**：在运行期判断任意对象所属的类、构造任意类的对象、获取任意类的成员与方法、调用任意对象的方法。这四条合起来意味着「代码执行什么」可以在运行时才决定，而不是编译时定死。

**典型场景**：JDBC 的 `Class.forName("com.mysql.cj.jdbc.Driver")` 靠反射加载驱动；Servlet 容器靠反射实例化 `web.xml` 里配置的类。二者共同点是「框架需要创建开发者写的类，但框架编译时并不知道那些类的存在」——这正是反射不可替代的位置。

**API 分布**：`java.lang.Class` 是入口，其余构造方法、字段、方法、修饰符类都在 `java.lang.reflect` 包里（素材把其中几个误写成 `java.lang`，订正见摘要页）。

**代价**：优点是把编译期依赖变成运行期依赖，换来极大的灵活性与解耦；缺点是性能开销（绕过 JIT 的静态优化）、可读性差（错误在运行期才暴露）、破坏封装（`setAccessible(true)` 能读写 private 成员），并带来安全风险。素材因此把 Java 描述为「准动态语言」。

反射与 [[类与对象]] 的关系是一体两面：前者是在运行期操作「类」这个对象，后者是编译期的模板与实例关系。反射中的 `Class` 对象本身也是一个对象，这是理解反射的钥匙。
