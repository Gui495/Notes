对 [[raw/Frontend_Backend/大数据安装]] 的提炼：用 JDK 17 + Hadoop 3.3.6 在一台机器上搭出伪分布式大数据环境的一条完整链路，从 4V 概念一路走到 HDFS 配置、启停、Shell 与 Java API。

## 这条线在讲什么

- 目标是**伪分布式**：一台机器上同时起 NameNode、DataNode、ResourceManager、NodeManager，先跑通再扩到完全分布式。
- 版本组合：JDK 17（素材前置写 17.0.16+，实际环境变量路径是 `jdk17012`）、Hadoop 3.3.6、ZooKeeper 3.8.4、HBase 2.6.0。
- HBase 版本有硬约束：**1.x 只支持 JDK 8**，配 JDK 17 必须 2.x。

## Hadoop 是什么（四模块）

| 模块 | 职责 |
|---|---|
| `hadoop-common` | 通用 I/O、工具、配置基础能力 |
| [[HDFS]] | 分布式文件系统，负责持久化存储 |
| [[YARN]] | 资源调度与作业管理，统一管 CPU/内存 |
| [[MapReduce]] | 跑在 YARN 上的分布式并行计算引擎，面向离线批处理 |

- 扩展方式：单台服务器可平滑扩到数千节点；每台节点**同时承担存储 + 计算**。
- [[MapReduce]] 三步：原始文件切分片分发到多个 MapTask → MapTask 输出 KV 经**分区 / 排序 / 分组** → 同 Key 数据进同一 ReduceTask → 聚合输出。

## 环境变量（`/etc/profile` 一次写全）

- `JAVA_HOME=/opt/soft/jdk17012`，`PATH` 前置。
- `HADOOP_OPTS` 加四个 `--add-opens`（`java.base/java.lang`、`java.base/java.io`、`java.management/com.sun.jmx.mbeanserver`、`java.base/sun.nio.ch`）——Hadoop/HBase 在 JDK 17 上靠这个放行 JPMS 反射。
- `HADOOP_HOME` 派生六项：`HADOOP_MAPRED_HOME`、`HADOOP_COMMON_HOME`、`HADOOP_HDFS_HOME`、`YARN_HOME`、`HADOOP_COMMON_LIB_NATIVE_DIR`、`HADOOP_CONF_DIR`。
- `ZOOKEEPER_HOME`、`HBASE_HOME`，且 `HBASE_OPTS="$HADOOP_OPTS"`（复用同一套反射放行）。

## 四个 XML 决定集群形状

| 文件 | 关键项 | 值 | 作用 |
|---|---|---|---|
| `core-site.xml` | `fs.defaultFS` | `hdfs://192.168.220.129:9000` | 默认文件系统地址（RPC 9000） |
| `core-site.xml` | `hadoop.tmp.dir` | `/opt/soft/hadoop-3.3.6/tmp` | 临时数据目录，权限错会拖死 DataNode |
| `hdfs-site.xml` | `dfs.replication` | `1` | 伪分布式单节点只能 1；生产默认 3 |
| `mapred-site.xml` | `mapreduce.framework.name` | `yarn` | 声明 MR 交给 YARN 跑 |
| `yarn-site.xml` | `yarn.resourcemanager.hostname` | `localhost` | RM 绑定主机 |
| `yarn-site.xml` | `yarn.nodemanager.aux-services` | `mapreduce_shuffle` | 开洗牌服务 |

`hadoop-env.sh` 里另需两项：五个 `*_USER=root`（学习环境以 root 起服务）与显式 `JAVA_HOME`。

## 启动前后各一步

1. **前置**：SSH 免密。`ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa` → 公钥追加 `~/.ssh/authorized_keys` → `chmod 600`（SSH 强制校验权限，权限过宽会拒绝登录）。集群启停脚本靠它免交互。
2. **初始化**：`hdfs namenode -format`，**只在首次执行一次**。重复格式化会让 clusterID 与 DataNode 不一致，DataNode 起不来——素材问题表第一条就是这个，修复手段是清空 tmp 后重格式化，等于丢数据。
3. **启停**：`start-dfs.sh` / `start-yarn.sh`（或 `start-all.sh`）、`stop-all.sh`；自定义配置目录用 `start-all.sh --config <绝对路径>` 或 `export HADOOP_CONF_DIR=...`。

## WebUI 端口（Hadoop 3.x）

| 服务 | 端口 |
|---|---|
| HDFS NameNode | 9870 |
| HDFS SecondaryNameNode | 9868 |
| YARN ResourceManager | 8088 |
| JobHistory Server | 19888（需单独启动） |

虚拟机 `/etc/hosts` 与宿主机 hosts 都要写 IP↔主机名映射，且要与 `core-site.xml` 的地址一致，否则浏览器打不开。

## 操作面

- **Shell**：`hadoop fs -mkdir -p`、`-ls -R /`、`-put 本地 /HDFS`、`-get /HDFS 本地`。
- **Java API**：`hadoop-client:3.3.6` + `maven-compiler-plugin` 3.11.0（`source/target/release=17`，`UTF-8`）。四类操作都靠同一个开头：

```java
FileSystem fs = FileSystem.get(new URI("hdfs://192.168.220.129:9000"), new Configuration(), "root");
```

分别是 `open` + `IOUtils.copyBytes`（下载）、`delete(path, false)`（递归参数）、`mkdirs`、`copyFromLocalFile`（上传）。
- 权限报错两条路：显式传用户 `"root"`，或 `dfs.permissions.enabled=false`（后者是绕过，不适合生产）。

## 配套 ZooKeeper / HBase

- `zoo.cfg`：`tickTime=2000`、`initLimit=10`、`syncLimit=5`、`dataDir=.../data`、`clientPort=2181`；`zkServer.sh start|stop`。
- `hbase-site.xml`：`hbase.cluster.distributed=true`、`hbase.rootdir=hdfs://192.168.220.129:9000/hbase`、`hbase.zookeeper.quorum=localhost`；`start-hbase.sh|stop-hbase.sh`。

## 素材勘误与不一致

1. **HBase 解压目录**：原文 `HBASE_HOME=/opt/soft/hbase-2.6.0-bin`。`hbase-2.6.0-bin.tar.gz` 解压出的顶层目录是 `hbase-2.6.0`（`-bin` 只出现在包名，不出现在目录名），对照同文的 `apache-zookeeper-3.8.4-bin`（ZooKeeper 的 dist 包目录名确实带 `-bin`）可见两者命名规则不同。**判定**：未重命名则 `HBASE_HOME` 指向不存在的路径。状态：已裁定。
2. **主机地址前后不一**：`core-site.xml` 与 Java 示例 1–3 用 `192.168.220.129`，示例 4（上传）用 `192.168.80.128`。同一集群不可能两个地址，示例 4 属复制残留。状态：已裁定。
3. **JDK 版本口径**：前置依赖写「17.0.16 或更高」，而所有 `JAVA_HOME` 路径与后两篇素材都是 `17.0.12`。状态：已裁定（内部不一致，按实际安装版本统一）。
4. **ZooKeeper dataDir 与 ZOOKEEPER_HOME 不同根**：`dataDir=/usr/local/software/apache-zookeeper-3.8.4-bin/data`，而 `ZOOKEEPER_HOME=/opt/soft/apache-zookeeper-3.8.4-bin`。二者不能同时对，疑似另一台机器的配置残留。状态：**待人类确认**。
5. **格式噪音**：代码块外残留 `bash` / `java` / `xml` / `props` 标注，不影响命令，属导出残留。
