对 [[raw/Frontend_Backend/MySQL_Operations]] 的提炼：事务的 ACID 与提交/回滚流程、四类索引的建立与取舍、`EXPLAIN` 的性能判读，以及 mysqldump 备份与两种恢复方式。本篇是整条 MySQL 线里密度最高的一篇。

## 事务

- 事务 = 把一组 SQL 放在**同一批次**内执行；其中一条出错，整批全部取消。

| 属性 | 含义 |
|---|---|
| 原子性 Atomicity | 要么全做，要么全不做 |
| 一致性 Consistency | 前后都满足业务约束（如转账总额不变） |
| 隔离性 Isolation | 并发事务互不干扰 |
| 持久性 Durability | 提交后即使宕机也不丢 |

## MySQL 的事务操作

```sql
SET AUTOCOMMIT = 0;   -- 关闭自动提交（用事务前必做）
START TRANSACTION;    -- 标记事务起点
-- ... 执行 SQL ...
COMMIT;               -- 成功：提交
ROLLBACK;             -- 失败：回到本次事务初始状态
SET AUTOCOMMIT = 1;   -- 恢复自动提交
```

- MySQL **默认自动提交**（`AUTOCOMMIT = 1`），所以单条语句执行完就已落库，`ROLLBACK` 无从撤销。
- 标准五步：关自动提交 → 开事务 → 执行 → 提交或回滚 → 开回自动提交。

素材案例（网上支付）：A 余额 2000、B 余额 10000，A 买 500 元商品。正确结果是 A 减 500 且 B 加 500；若 B 未加上，就回滚 A 的 500，保证总额守恒——这正是 ACID 里「一致性」的具体化。

## 索引

作用：提高查询速度、保证唯一性、加速表连接实现参照完整性、减少分组排序时间、优化全文检索字段。

| 类型 | 关键字 | 特点 |
|---|---|---|
| 主键索引 | `PRIMARY KEY` | 唯一标识一条记录；**一张表只能有一个**；确定记录物理位置 |
| 唯一索引 | `UNIQUE` | 避免某列值重复；**可以有多个** |
| 常规索引 | `INDEX` / `KEY` | 快速定位，应加在查找条件字段 |
| 全文索引 | `FULLTEXT` | 面向大文本检索，适合大型数据集 |

```sql
-- 主键
GradeID INT(11) AUTO_INCREMENT PRIMARY KEY
-- 唯一
GradeName VARCHAR(32) NOT NULL UNIQUE
-- 常规（建表时或建表后追加）
INDEX ind (studentNo, subjectNo)
ALTER TABLE result ADD INDEX ind (studentNo, subjectNo);
-- 全文
FULLTEXT(StudentName)  -- 素材示例：ENGINE=MYISAM
```

### 管理索引

- 创建：建表时声明，或 `ALTER TABLE 表名 ADD 索引类型(数据列名)`。
- 删除：`DROP INDEX 索引名 ON 表名`、`ALTER TABLE 表名 DROP INDEX 索引名`、`ALTER TABLE 表名 DROP PRIMARY KEY`。
- 查看：`SHOW INDEX FROM 表名`（`SHOW KEYS` 等价）。

### 索引准则

- 不是越多越好——每个索引都要在插入/删除/更新时维护。
- 不给经常变动的列加索引；小数据量表不建议加。
- 一般加在**查找条件**（`WHERE`、`JOIN`、`ORDER BY`）字段上。

## EXPLAIN

```sql
EXPLAIN 表名;            -- 等同 DESC 表名
EXPLAIN SELECT 语句;
```

- 句末用 `\G` 竖排显示，宽表更易读。
- 作用是分析 SQL 执行性能（是否走索引、扫多少行）。

## 备份与恢复

- 为什么备份：防丢、便于数据转移。
- 三条路：`mysqldump` 工具、图形工具（SQLyog）、直接拷贝数据文件与配置。

```bash
mysqldump -h 主机名 -u 用户名 -p [options] [table1 table2 ...] > path/filename.sql
mysqldump -u root -p myschool > d:/myschool.sql
```

| 选项 | 作用 |
|---|---|
| `--add-drop-table` | 导出脚本里加 `DROP TABLE IF EXISTS`，默认开启 |
| `--add-locks` | INSERT 前后包 `LOCK/UNLOCK TABLES`，默认开启 |
| `-t` / `--no-create-info` | 不导出 `CREATE TABLE`，只要数据 |
| `-c` / `--complete-insert` | 每条 INSERT 带上字段名 |
| `-d` / `--no-data` | 只导表结构，不导行 |
| `-w` / `--where` | 只导满足条件的记录 |
| `--opt` | 一组常用选项的速记（默认已启用） |

恢复两条路：

```sql
SOURCE /path/db_name.sql;          -- 在 mysql 命令行内执行，需绝对路径且运行用户有读权限
```
```bash
mysql -u root -p dbname < /path/db_name.sql
```

- `SOURCE` 前要**先建库或选库**。
- 纯 SQL 数据导出/导入：`SELECT * INTO OUTFILE 'file' FROM tbl;`（目标文件不能已存在，否则报错）、`LOAD DATA INFILE 'file' INTO TABLE tbl [FIELDS ...];`

## 素材订正（已裁定）

### 订正一：EXPLAIN 连接类型串

**原文错值**：§3.9「连接类型从好到差：const、eq_reg、ref、range、indexhe、ALL」。

**正确值**：`const`、`eq_ref`、`ref`、`range`、`index`、`ALL`（另有 `system`、`fulltext`、`ref_or_null`、`index_merge`、`unique_subquery`、`index_subquery` 等取值，素材未列）。

**判定证据**：① `eq_reg` 与 `indexhe` 都不是 `EXPLAIN` 输出 `type` 列的合法取值，合法值是 `eq_ref`（等值联表，每行唯一匹配）与 `index`（全索引扫描）；② 反推：MySQL 全文检索相关类型里没有 `reg` 后缀的成员，且「indexhe」夹在 `range` 与 `ALL` 之间，位置正好是 `index` 应处的位置，说明是抄录时把 `eq_ref` 误作 `eq_reg`、`index` 后多粘了两个字符。

### 订正二：全文索引的引擎限制

**原文错值**：§3.6「全文索引……只能用于 MyISAM 类型数据表」。

**正确值**：这是 MySQL 5.5 及更早的限制；**MySQL 5.6.4 起 InnoDB 也支持 `FULLTEXT`**，素材针对的 MySQL 8.0.30 默认引擎就是 InnoDB，因此 8.0 上「只能 MyISAM」不成立。素材示例写 `ENGINE=MYISAM` 只是沿用旧教材写法。

**判定证据**：① 素材自身装的是 8.0.30（见 [[2026-10-27-MySQL8安装]]），而 8.0 早已移除对 MyISAM 系统表的依赖、默认引擎为 InnoDB，若全文索引真的只支持 MyISAM，则 8.0 下的文本检索将无法建在主引擎上，与官方文档记载的 InnoDB `FULLTEXT` 支持矛盾；② 可溯源：InnoDB 自 5.6.4 起支持全文索引与检索，见 `## 参考` 中的条目。

## 素材缺失

- 事务只讲单语句级提交/回滚，**没有隔离级别**（`READ COMMITTED`、`REPEATABLE READ` 等）与并发异常（脏读、不可重复读、幻读）。
- 索引未讲 B+ 树结构、复合索引的**最左前缀**原则、索引失效场景。
- `EXPLAIN` 只说了怎么用，**没有给出一次真实输出**与逐列解读。
- 备份没讲二进制日志（binlog）与增量恢复、没讲 `--single-transaction` 这类一致性快照选项。
