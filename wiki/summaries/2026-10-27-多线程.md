对 [[raw/Frontend_Backend/Multithreading]] 的提炼：进程与线程的分工、两种建线程方式、`run()` 与 `start()` 的关键差别、调度四方法、共享数据为什么错乱以及 `synchronized` 的两种写法。

## 进程与线程

| 概念 | 定义 | 内存 |
|---|---|---|
| 进程 | 应用程序的执行实例 | 独立内存空间与系统资源 |
| 线程 | CPU 调度和分派的基本单位，进程中执行运算的最小单位，可完成独立顺序控制流程 | 同一进程内共享资源 |

- 多线程 = 一个进程内同时运行多个线程、完成不同工作。
- 关键事实：多个线程**交替占用 CPU**，不是真正并行；每次执行多久由 CPU 时间片决定。
- 好处：充分利用 CPU、简化编程模型、用户体验好。

## 主线程

- Java 用 `java.lang.Thread` 类支持多线程，`main()` 是主线程入口。
- 主线程必须**最后**完成，因为它执行各种关闭动作。
- 取当前线程：`Thread t = Thread.currentThread(); t.getName();`

## 建线程方式一：继承 Thread

1. 定义 `MyThread extends Thread`。
2. 重写 `run()`，写线程执行体。
3. `new` 出对象，调 `start()`。

```java
public class MyThread extends Thread {
    public void run() { /* 线程执行体 */ }
}
new MyThread().start();
```

## `run()` 与 `start()` 的区别（重点）

- 直接调 `run()`：只是**普通方法调用**，仍在主线程里，只有一条执行路径。
- 调 `start()`：启动新线程，主线程与子线程交替执行。

## 建线程方式二：实现 Runnable

1. `MyRunnable implements Runnable`。
2. 实现 `run()`。
3. `new Thread(myRunnable).start();`

| | 继承 Thread | 实现 Runnable |
|---|---|---|
| 编写 | 简单，可直接操作线程对象 | 略绕，要套一层 Thread |
| 继承限制 | 受 Java 单继承限制 | 避免单继承局限 |
| 资源共享 | 多个线程各持一份实例 | 便于多个线程共享同一份资源 |

## 线程五状态

创建 → 就绪 → 运行 → 阻塞 → 死亡。

## 线程调度

| 方法 | 作用 |
|---|---|
| `void setPriority(int p)` | 改优先级，1~10，1 最低，**默认 5** |
| `static void sleep(long millis)` | 休眠指定毫秒，进入阻塞；到点回到可运行 |
| `void join()` | 当前线程暂停，等该线程结束后再继续（需处理 `InterruptedException`） |
| `static void yield()` | 暂停当前线程，让**同优先级**线程有机会运行；线程仍处就绪态，不进阻塞 |
| `void interrupt()` | 中断线程 |
| `boolean isAlive()` | 是否活动 |

- 优先级只是「获得 CPU 的概率较大」，不是保证。
- `Thread.MAX_PRIORITY` / `Thread.MIN_PRIORITY` 是常量写法。

## 共享数据为什么会错

素材用网络购票举例，三种症状：

- 不是从第 1 张票开始；
- 多人抢到同一张票；
- 有些票号根本没被抢到。

原因一句话：多个线程并发修改同一份共享数据，而「判断余量 → 扣减 → 打印」不是**原子操作**，线程随时可能在中间被切走。

## 同步的两种写法

```java
// 同步方法（两种修饰符顺序都可）
public synchronized void sale() { ... }
synchronized public void sale() { ... }

// 同步代码块
synchronized (syncObject) { ... }   // syncObject 通常为 this
```

`synchronized(this)` 的三条行为规则：

1. 同一时刻只能有一个线程进入 `synchronized(this)` 代码块。
2. 一个线程在 `synchronized(this)` 里时，**其他** `synchronized(this)` 块同样被锁定（锁是对象，不是代码段）。
3. 但其他线程**仍可**访问该资源的非同步代码。

## 线程安全 vs 非线程安全

- `ArrayList.add()` 是非同步方法，多线程添加可能数据不一致 → `ArrayList` 非线程安全。
- 规律：线程安全 = 加了同步 = 效率低 = 适合多线程并发共享资源；非线程安全 = 不同步 = 效率高 = 适合单线程。

| 对照 | 线程安全 | 非线程安全 |
|---|---|---|
| 映射 | `Hashtable`（键值都不允许 null） | `HashMap`（键值都允许 null） |
| 字符串 | `StringBuffer` | `StringBuilder` |

## 并发包与第三种建线程方式

- `java.util.concurrent` 提供：阻塞队列 `BlockingQueue`、延迟队列 `DelayQueue`、闭锁 `CountDownLatch`、线程池 `ExecutorService`。
- 第三种建线程方式：`Callable`，能拿到线程执行结果（素材只提一句，未给 `Future` 用法）。
