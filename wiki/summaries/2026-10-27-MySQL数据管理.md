对 [[raw/Frontend_Backend/MySQL_Data_Management]] 的提炼：DML 三条语句（INSERT / UPDATE / DELETE）的语法骨架与易错点，外加 TRUNCATE 与 DELETE 的差别。写进去的数据怎么读出来，见 [[DQL查询]]。

## DML 是什么

- 数据库的两大意义：数据存储、数据管理。
- 管理数据的两条路：图形工具（SQLyog 等）或 **DML 语句**。
- DML（数据操作语言）用于操作数据库对象中**所包含的数据**——动的行，不是表结构。语句三位一体：`INSERT` 添加、`UPDATE` 更新、`DELETE` 删除。

## INSERT

```sql
INSERT INTO 表名 [(字段1, 字段2, ...)]
VALUES ('值1', '值2', ...);
```

- 字段或值之间用**英文逗号**；中文逗号是最常见的低级错误。
- 字段部分可省略，但省略时**值必须与表结构列顺序一一对应且数量一致**。
- 一次插多行：`VALUES (...),(...),(...)`，用逗号隔开。

```sql
INSERT INTO grade (GradeName) VALUES ('大一'),('大二'),('大三'),('大四');
```

素材的 `student` 表结构：学号、姓名、性别、年级、手机号、地址、邮箱、身份证。

## UPDATE

```sql
UPDATE 表名
SET column_name = value [, column_name2 = value2, ...]
[WHERE condition];
```

- `value` 可以是具体值、变量、表达式，或**嵌套的 SELECT 结果**（这是「用查询结果反写」的入口）。
- `WHERE` 不写 = 修改**全表**所有行——最常见的事故来源。
- 可用运算符：`=`、`!=`、`>`、`<`、`>=`、`<=`、`BETWEEN ... AND ...`、`AND`、`OR`。

```sql
UPDATE student SET email='student1013@bdqn.cn', LoginPwd='000000' WHERE StudentNo=1013;
UPDATE subject SET ClassHour = ClassHour - 10 WHERE ClassHour > 110 AND GradeID = 1;
```

第二例是重点：`SET` 右边可以引用**本列原值**做运算（在原值上减 10），不是只能用常量。

## DELETE

```sql
DELETE FROM 表名 [WHERE condition];
```

- 同样：不写 `WHERE` 就删全表数据（表结构仍在）。

## TRUNCATE

```sql
TRUNCATE [TABLE] table_name;
```

| 对比项 | DELETE | TRUNCATE |
|---|---|---|
| 删数据 | 是 | 是 |
| 删表结构 / 索引 / 约束 | 否 | 否（都保留） |
| 速度 | 慢（逐行） | 快 |
| `AUTO_INCREMENT` 计数器 | 不重置 | **重置** |
| 可否带 `WHERE` | 可以 | 不能（只能整表） |

## 分类上的存疑（编译者补充，非素材原意）

素材把 `TRUNCATE` 与 DML 并列讲。按 SQL 的功能分类，`TRUNCATE` 通常被归入 DDL（数据定义语言）而非 DML，且它是隐式提交、不可回滚的——这一点素材完全没提，练习时容易以为「删错了还能 rollback」。**该条属编译者补充，未经素材确认，建议人类核实后固化。**
