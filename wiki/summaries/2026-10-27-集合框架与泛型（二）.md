## Map 接口

- 专门处理**键值映射**数据，按 key 操作 value；最常用实现 `HashMap`。
- key 不允许重复（重复 put 会覆盖），value 可重复。

| 方法 | 说明 |
|---|---|
| `Object put(Object key, Object val)` | 存入键值对 |
| `Object get(Object key)` | 按键取值，**键不存在返回 null** |
| `Object remove(Object key)` | 删除该键值对 |
| `int size()` | 元素个数 |
| `Set keySet()` | 返回键的 Set |
| `Collection values()` | 返回值的 Collection |
| `boolean containsKey(Object key)` | 是否含指定键 |

三种遍历：

1. Iterator：对 `keySet()` 或 `values()` 迭代。
2. 增强 for：`for (Object k : map.keySet())`。
3. 键值对：拿到 key 后 `get(key)` 取值（素材只给名称，未给 `entrySet()` 代码）。

## 泛型

- 要解决的问题：集合默认收 `Object`，取出来必须强制类型转换，类型错了要到**运行期**才抛异常。
- 本质：**参数化类型**——把对象类型作为参数，指定到其他类或方法上。
- 历史：JDK 5.0 用泛型改写了集合框架的所有接口和类。
- 写法：

```java
ArrayList<Student> students = new ArrayList<Student>();
students.add(student);
// students.add(poem);  // 编译期就报错
```

- 三个好处：约束元素类型；数据不再需要转成 `Object` 再转回来；除指定元素类型外，用法与普通集合完全一样。
- 效果是**把运行期的类型错误提前到编译期**，这是它真正值钱的地方。

## Collections 工具类

- 集合框架把不同数据结构的算法集中放在工具类里，`Collections` 定义一组操作集合的**静态方法**。
- `Collections`（操作类）≠ `Collection`（接口）——素材明确点出这一对易混。
- 常用静态方法：`sort()` 排序、`binarySearch()` 查找、`max()` / `min()` 求最值。
- 要让自定义对象可排序：实现 `Comparable` 接口，重写 `compareTo()` 方法。

## 素材缺失

- 未给 `HashMap` 的遍历完整代码（三种遍历只列了名字），也未涉及 `entrySet()`。
- 泛型只讲到「泛型集合」，未涉及泛型类/泛型方法/通配符 `? extends` 等。
- `Comparable` 只说「重写 `compareTo()`」，没有给出方法签名与返回值含义（负数/0/正数代表的大小关系）。
