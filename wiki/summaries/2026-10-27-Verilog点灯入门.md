盘古 100Pro+（MES2L676-100HP）开发板从零跑通点灯的 Verilog 入门笔记，覆盖语法骨架、RTL 与 Testbench 的分工、引脚约束下载，以及一份 17 行的排错表。

## 一、工程目标与三个必须核对的硬件事实

- 板卡：盘古 100Pro+（MES2L676-100HP），配套 小眼睛 FMC 子卡与摄像头。
- 点灯阶段**先不接 FMC 和摄像头**，只用开发板本身跑通：编译 → 约束 → 综合 → 布局布线 → 生成位流 → 下载。
- 动手前必须确认三件事，任一项搞错都会表现为「灯不亮」或「亮灭相反」：
  1. **系统时钟频率**——常见 27MHz，但须查原理图；若不是 27MHz，计数器上限要重算。
  2. **LED 极性**——高电平点亮还是低电平点亮。
  3. **复位按键极性**——低电平有效时用 `negedge rst_n` + `if (!rst_n)`。
- 素材明确警告：引脚号、时钟、极性一律以官方原理图、实验手册和配套约束文件为准，**不要照抄网上**。

## 二、最小可综合骨架

```verilog
module blink (
    input  clk,
    input  rst_n,
    output reg led
);
    localparam CNT_MAX = 25'd13_499_999;
    reg [24:0] cnt;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            cnt <= 25'd0;
            led <= 1'b0;
        end else if (cnt >= CNT_MAX) begin
            cnt <= 25'd0;
            led <= ~led;
        end else begin
            cnt <= cnt + 1'b1;
        end
    end
endmodule
```

骨架要素：端口声明、`localparam`、内部 `reg`、时序 `always`、`if/else`、`begin/end`、非阻塞赋值。细节见 [[Verilog模块]]。

## 三、三条类型铁律

- `input` 只能是 `wire`；`output` 可 `wire` 可 `reg`。
- **`assign` 左边必须是 `wire`；`always` 里被赋值的必须是 `reg`**。
- `always @(*)` 里所有分支都必须给输出赋值，否则综合出锁存器（`latch inferred`）。

见 [[wire与reg]]。

## 四、时序逻辑与组合逻辑两套模板

| 项目 | 时序逻辑 | 组合逻辑 |
|---|---|---|
| 敏感列表 | `posedge clk` / `negedge rst_n` | `always @(*)` |
| 赋值符号 | 非阻塞 `<=` | 阻塞 `=` |
| 综合结果 | 触发器/寄存器 | 纯组合逻辑 |
| 典型用途 | 计数器、状态机、流水灯 | 译码、简单逻辑运算 |

两条初学铁律：`always @(posedge clk)` 里一律 `<=`；`always @(*)` 里一律 `=` 且分支完整。见 [[阻塞与非阻塞赋值]]。

## 五、点灯与流水灯的关键计算

- **计数上限**：27MHz 下 0.5 秒 = 27 000 000 × 0.5 = 13 500 000 个周期，计 `0` 到 `13_499_999`。
- **位宽**：2²⁴ = 16 777 216 > 13 499 999，故 24 位够用；素材代码取 25 位更保险。
- **流水灯循环左移**：`led_status <= {led_status[6:0], led_status[7]}`，拼接实现 8 位环形移位。
- **极性处理**：低电平点亮的板子输出取反（`led = ~led_status` 或顶层 `assign led = ~led_n`），以原理图为准。

## 六、Testbench 不可综合

- 无端口，用 `initial` 产生激励、`#` 延时、`forever` 产生时钟、`$finish` 结束。
- 仿真时把 `CNT_MAX` 覆盖成小值（如 `25'd9`），否则要真跑 0.5 秒仿真时间。
- 详见 [[RTL设计与Testbench]]。

## 七、引脚约束与下载

- 至少约束三个信号：`clk`、`rst_n`、`led`。
- 引脚号四路来源：实验手册「接口列表」、板卡原理图、官方例程约束文件、PDS 的 User Constraint Editor；约束文件常见扩展名 `.fdc` / `.uce`。
- 流程九步：建工程 → 加源文件 → 设顶层 → 加约束 → 综合 → 布局布线 → 生成位流 → 连下载器 → 观察 LED。
- 见 [[引脚约束与位流]]。

## 八、排错表里最高频的六条

| 现象 | 首查 |
|---|---|
| LED 完全不亮 | 引脚约束错、下载失败、极性反、复位一直按住 |
| LED 常亮或常灭 | 计数器没翻转、复位未释放、极性反 |
| 闪烁快慢不对 | 板卡实际时钟不是 27MHz、`CNT_MAX` 算错、位宽溢出 |
| 综合报 `cannot assign to wire` | 在 `always` 里给 `wire` 赋值 |
| 综合警告 `latch inferred` | 组合逻辑分支不全 |
| 仿真对但板上不对 | 仿真时钟频率、复位极性、LED 极性三处与实际不符 |

其余：多位宽常量告警（显式写 `25'd...`）、同一 `reg` 被多个 `always` 驱动、RTL 里用 `#` 延时、依赖 `initial` 初始化、顶层模块选错、约束文件没加入。

## 九、素材自身的局限

- 本文原始形态是「可直接复制保存的 Markdown 笔记」，不是课堂记录或官方手册。
