对 [[raw/Frontend_Backend/Reflex_Mechanism]] 的提炼：反射是什么、它把「编译期绑定」换成「运行期查找」的四类能力、常用 API 所在的包，以及它为什么既是 Java 被称为准动态语言的原因、又是性能与封装的双刃剑。本篇素材极短，只有定义与结论，没有代码。

## 定义

反射是指在**程序运行期间**，能够观察和修改类、或类的对象的属性与行为的特性。

- 对照理解：普通调用在**编译期**就把「调哪个方法」写死了；反射把这一步推迟到**运行期**，靠字符串名字去找。
- 常见使用场景：JDBC 连接数据库、Servlet 在 Web 容器中的加载和运行——共同点是「框架先写好，具体类后到」，框架编译时根本不知道用户会写哪个类。

## 四类能力

1. 运行时获取类的**修饰符、包名、类名、实现的接口、继承的父类**。
2. 运行时获取类的所有**属性名、修饰符、属性类型**。
3. 运行时获取所有**方法**，及方法的返回值类型、方法名、参数数量、参数类型。
4. 运行时**调用**已加载类的方法。

## 常用 API

| 类 | 职责 |
|---|---|
| `java.lang.Class` | 类的元信息入口 |
| `java.lang.reflect.Method` | 方法 |
| `java.lang.reflect.Constructor` | 构造方法 |
| `java.lang.reflect.Field` | 属性 |
| `java.lang.reflect.Modifier` | 修饰符解析 |

## 素材订正（已裁定）

**原文错值**：§3 写作 `java.lang.Constructor`、`java.lang.Field`、`java.lang.Modifier`。

**正确值**：`java.lang.reflect.Constructor`、`java.lang.reflect.Field`、`java.lang.reflect.Modifier`；只有 `Class` 在 `java.lang`，反射的其余成员类都在 `java.lang.reflect`。

**判定证据**：① 素材同一条清单里 `Method` 写的是 `java.lang.reflect.Method`——同一个包下的 `Method`、`Field`、`Constructor`、`Modifier` 不可能分属两个包，说明这三行是漏写了 `.reflect`；② `java.lang` 是自动导入的核心包，若这四类真在其中，反射就无需单独 import `java.lang.reflect.*`，而所有 Java 教材都要求导入该包，反推即知原文有误。

## 实战四件事

素材列的「反射实战」其实是四个递进任务，但没有一行代码：

1. 用反射获取类的信息。
2. 获取构造函数的参数列表，并通过构造函数**实例化**类。
3. 获取所有方法信息，调用 setter 完成属性赋值。
4. 获取所有属性名和类型，并给其中一个属性赋值。

## 案例：为什么需要反射

- 场景：购物网站要针对节假日设计不同优惠方案。
- 小王的做法：每个优惠方案写一个实现类，再把「用哪个类」硬编码进系统。
- 后果：代码耦合度高、维护成本大——每加一个节日就要改系统代码并重新编译。
- 解决思路：用反射，运行时按名字加载类、调用方法，新增方案只需加类、不改系统。

## 优缺点

| 优点 | 缺点 |
|---|---|
| 提高灵活性 | 性能开销（运行期查找，绕开编译期优化） |
| 降低耦合 | 破坏封装（可访问 private 成员） |
| — | 安全风险 |

素材的定性判断：反射是 Java 被视为**准动态语言**的关键特性。
