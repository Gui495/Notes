对 [[raw/Frontend_Backend/DQL_Command]] 的提炼：`SELECT` 的完整子句骨架与各子句的分工——别名、去重、`WHERE` 与 `LIKE` / `IN` / `BETWEEN`、四种连接、排序、分页、子查询、统计函数与分组过滤。数据怎么进去见 [[DML数据管理]]。

## DQL 的定位

- DQL（Data Query Language，数据查询语言）用于查询数据库数据，典型语句是 `SELECT`。
- 覆盖范围：单表简单查询，多表复杂查询与嵌套查询。
- 素材的定性：数据库语言中**最核心、最重要、使用频率最高**的语句。

## SELECT 骨架

```sql
SELECT [ALL | DISTINCT]
       { * | table.* | [table.field1 [as alias1][, table.field2 [as alias2]][, ...]] }
FROM table_name [as table_alias]
[ LEFT|RIGHT|INNER JOIN table_name2 ]   -- 联合查询
[ WHERE ... ]        -- 结果需满足的条件
[ GROUP BY ... ]     -- 按哪些字段分组
[ HAVING ... ]       -- 分组后必须满足的次要条件
[ ORDER BY ... ]     -- 排序
[ LIMIT { [offset,] row_count | row_count OFFSET offset } ];
```

- 记法：`[]` 可选、`{}` 必选。
- 注释写法：`#` 或 `/* */`。

## 选列与别名

- `select * from student;` 效率低，不推荐——要多少列点多少列。
- 多表有同名字段时必须加表名前缀：`SELECT student.StudentNo, StudentName, StudentResult FROM student, result;`
- `AS` 三种用途：给列取别名、给表取别名、给计算结果取名字；`AS` 可省略。

```sql
SELECT StudentNo AS "学号" FROM student;
SELECT a.StudentNo FROM student AS a;
SELECT Phone+1 AS Tel FROM student;
```

## 去重与表达式列

- `DISTINCT` 去重：**所有返回列的值都相同**才算重复，只保留一条；`ALL` 是默认值（返回全部）。
- 表达式 = 文本值、列值、`NULL`、函数、操作符的组合；可用于 SELECT 结果列、`ORDER BY` / `HAVING` 子句、DML 的 `WHERE` 条件。

```sql
SELECT version(), 100*3;
SELECT SubjectName "课程名称", ClassHour+10 AS "新学时" FROM subject;
```

## WHERE 条件查询

- 逻辑操作符：`AND`/`&&`（同时真）、`OR`/`||`（一个真）、`NOT`/`!`（取反）。
- 比较操作符：`IS NULL` / `IS NOT NULL`、`BETWEEN a AND b`、`LIKE`、`IN (a1,a2,...)`。
- 两条硬约束：**数值类型之间**才能算术运算；**相同数据类型**才能比较。

### BETWEEN / LIKE / IN / NULL

| 子句 | 语义 | 例 |
|---|---|---|
| `BETWEEN 110 AND 120` | 闭区间，等价于 `>=110 AND <=120` | 查学时 110~120 |
| `LIKE "%数学%"` | `%` 匹配 0 到任意多字符 | 模糊匹配名称 |
| `LIKE "李_"` | `_` 匹配**恰好一个**字符 | 姓李且名两字 |
| `IN (100,110,120)` | 枚举命中，比多个 OR 更简洁、效率更高 | 学时是这三者之一 |
| `IS NULL` / `IS NOT NULL` | `NULL` 是「无值」，不等于 0，也不等于空串；只能用 `IS` 比较，不能用 `=` | 查未填字段 |

## 连接查询

| 类型 | 返回 |
|---|---|
| `INNER JOIN` | 至少有一侧匹配的行 |
| `LEFT JOIN` | 左表全保留，右表无匹配处补 NULL |
| `RIGHT JOIN` | 右表全保留，左表无匹配处补 NULL |

```sql
SELECT SubjectName, GradeName
FROM subject INNER JOIN grade
ON subject.GradeID = grade.GradeID;
```

- 等值连接与内连接等价：`FROM subject, grade WHERE subject.GradeID = grade.GradeID`；不写 `WHERE` 等值条件就是**非等值连接**（笛卡尔积）。
- **自连接**：表与自己连接。素材案例是 `category` 表（`categoryId`、`categoryName`、`pid`），用它同时查出父栏目名与子栏目名。

## 排序与分页

```sql
SELECT ... ORDER BY 字段 [ASC|DESC];   -- 默认 ASC
SELECT * FROM result LIMIT 5;          -- 前 5 条
SELECT * FROM result LIMIT 5,10;       -- 跳过 5 条再取 10 条，即第 6~15 条
```

- `LIMIT m,n` 里 `m` 是偏移量、`n` 是条数；只写一个数字时偏移量为 0。
- 分页公式：第 k 页（每页 n 条）→ `LIMIT (k-1)*n, n`。素材只说了「常用作分页显示」，没给公式。

## 子查询

- 在 `WHERE` 条件里再套一个查询。
- 素材例题：查课程为《高等数学-2》且分数不低于 80 分的学号与姓名。
- 多个子查询时**由里及外**求解；子查询结果一般是集合，建议配 `IN` 使用。

## 统计函数与分组

| 函数 | 说明 |
|---|---|
| `COUNT()` | 满足条件的记录数 |
| `SUM()` | 数字字段/表达式的总和 |
| `AVG()` | 平均值 |
| `MAX()` / `MIN()` | 最大 / 最小 |

- 别用 `COUNT(*)` 之外的 `*` 形式，效率低。

```sql
SELECT 课程名, MAX(StudentResult) 最高分, MIN(StudentResult) 最低分, AVG(StudentResult) 平均分
FROM result
GROUP BY 课程名
HAVING AVG(StudentResult) >= 60;
```

- `GROUP BY` 可依据多个字段、并**依次分组**；`HAVING` 过滤的是**分组后的结果**，`WHERE` 过滤的是分组前的行——这是二者唯一的分界线。

## 素材订正（已裁定）

**原文错值**：§2 骨架写作 `[ left|out|inner join table_name2 ]`。

**正确值**：`[ LEFT | RIGHT | INNER JOIN table_name2 ]`，`out` 应为 `right`。

**判定证据**：① SQL / MySQL 的 JOIN 类型只有 `INNER`、`LEFT [OUTER]`、`RIGHT [OUTER]`、`CROSS`（以及 `STRAIGHT_JOIN`），不存在 `OUT JOIN` 这种写法；`OUTER` 只是 `LEFT/RIGHT` 的可选后缀，不能单用；② 同一素材 §12 的「JOIN 对比」表只列了 `INNER JOIN`、`LEFT JOIN`、`RIGHT JOIN` 三种，与骨架里的 `out` 自相矛盾，说明骨架处是把 `right` 抄成了 `out`。

## 素材缺失

- 只有 `SELECT` 语言部分，**没有 DDL**（建库建表、`CREATE`/`ALTER`/`DROP`）、没有 DCL（授权）、没有视图、存储过程、触发器。
- 子查询只讲「嵌套在 WHERE」，未讲 `EXISTS`、`ANY`/`ALL`、派生表（FROM 子句子查询）。
- 未讲聚合与 `NULL` 的交互（`COUNT(列)` 跳过 NULL）、未讲 `GROUP BY` 与 `ONLY_FULL_GROUP_BY`。
- 所有例题都基于素材内置的 `student` / `subject` / `result` / `grade` 表，**没有给出建表语句**，无法直接复现。
- 「多表同名字段必须加表名」只说了一句，没有给出报错示例（`Column 'StudentNo' in field list is ambiguous`）。
