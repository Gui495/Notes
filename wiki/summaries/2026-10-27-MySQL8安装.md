对 [[raw/Frontend_Backend/MySQL8]] 的提炼：在 CentOS 7 上用二进制 tar 包安装 MySQL 8.0.30 的九步流程——卸 mariadb、装依赖、解压、授权、初始化、改配置、起服务、改密码开远程、设开机启动。装好之后进入 [[DML数据管理]] 与 [[DQL查询]]。

## 安装九步

| 步 | 动作 | 关键命令 |
|---|---|---|
| 1 | 卸载 mariadb（与 MySQL 冲突） | `rpm -qa \| grep mariadb` → `rpm -e --nodeps 文件名` |
| 2 | 装前置依赖 | `yum -y install libaio numactl` |
| 3 | 解压并建目录 | `tar -xvf` → `tar -zxvf` → `mv mysql-8.0.30-el7-x86_64/ mysql` → `mkdir -p mysql/data` |
| 4 | 授权 | `chown -R root:root /usr/local/mysql/`、`chmod -R 755` |
| 5 | 初始化 | `./mysqld --initialize --user=root --datadir=/usr/local/mysql/data --basedir=/usr/local/mysql` |
| 6 | 改配置 | 改 `support-files/mysql.server` 里的 `$bindir/mysqld_safe --user=root`；新建 `/etc/my.cnf` |
| 7 | 起服务 + 软链 | `mysql.server start`，`ln -s` 三处，`service mysql restart` |
| 8 | 登录取改密码、开远程 | `alter user 'root'@'localhost' identified by 'ok';` + `update user set user.Host='%' ...` |
| 9 | 开机自启 | `cp mysql.server /etc/init.d/mysqld` → `chmod +x` → `chkconfig --add mysqld` → `reboot` |

## 第 5 步：初始化

```sh
cd /usr/local/mysql/bin/
./mysqld --initialize --user=root --datadir=/usr/local/mysql/data --basedir=/usr/local/mysql
# 此处要复制你的随机密码
```

- MySQL 8 用 `--initialize` 生成临时随机 root 密码，只打印一次，**必须先抄下来**，否则只能删库重初始化。
- 与 5.7 的 `mysql_install_db` 是两代不同命令。

## 第 6 步：`/etc/my.cnf`

- `[client]` / `[mysql]`：`port = 3306`、`socket = /usr/local/mysql/data/mysql.sock`、`default-character-set = utf8mb4`。
- `[mysqld]`：`character-set-client-handshake = FALSE`、`character-set-server = utf8mb4`、`collation-server = utf8mb4_general_ci`、`init_connect = 'SET NAMES utf8mb4'`、`datadir = /usr/local/mysql/data`、`skip-external-locking`。
- `[mysqldump]`：`quick`、`max_allowed_packet = 16M`——与备份章节直接相关，见 [[2026-10-27-MySQL事务索引与备份]]。
- `[myisamchk]`、`[mysqlhotcopy]`：两个老工具的参数块，8.0 里基本用不上，属模板残留。
- 字符集这一组配置是整篇里最实用的部分：`character-set-server = utf8mb4` + `init_connect` 决定了建库后客户端会话的默认编码，漏了就会中文乱码。

## 第 8 步：改密码并允许远程

```sql
mysql -uroot -p
alter user 'root'@'localhost' identified by 'ok';
use mysql;
update user set user.Host='%' where user.User='root';
flush privileges;
```

- `flush privileges;` 让 `mysql.user` 表的改动立即生效。
- 把 host 改成 `'%'` 等于允许任意 IP 用 root 连——学习环境可以，生产环境是高风险动作。

## 素材前后不一致 / 缺失

- **socket 路径自相矛盾**：`my.cnf` 里 socket 定为 `/usr/local/mysql/data/mysql.sock`，但第 7 步执行 `ln -s /usr/local/mysql/mysql.sock /var/mysql.sock`，源路径少了 `data/`，该软链必然指向不存在的文件。
- **服务注册重复**：第 7 步已 `ln -s .../mysql.server /etc/init.d/mysql`，第 9 步又 `cp` 同一个文件到 `/etc/init.d/mysqld`，两个名字指向不同机制（软链 vs 副本），后者的 `chkconfig --add` 才是生效的那个。
- **以 root 运行 mysqld**：`--user=root`、`--initialize --user=root`、`chown root:root` 三处一致地把服务跑在 root 下，这是素材的明确选择，但等于数据库被攻破即整机失守。
- 未写防火墙放行 3306、未写 SELinux 处理；第 9 步直接 `reboot` 而不先验证服务能否自启。
