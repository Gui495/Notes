对 [[raw/Frontend_Backend/Hive]] 的提炼：把 Hive 4.1.0 架在 Hadoop 3.3.6 + MySQL 8.0 之上的安装流程，重点是 `hive-site.xml` 的几类关键项与 Metastore 初始化。

## 版本与依赖

| 组件 | 版本 | 素材给的验证命令 |
|---|---|---|
| JDK | 17.0.12 | `java -version` |
| [[Hadoop]] | 3.3.6 | `hdfs dfs -ls /` |
| MySQL | 8.0 | `systemctl status mysqld` |
| Hive | 4.1.0 | — |

官方口径（2026-10 核实）：4.1.0 于 **2025-07-31** 发布，是**首个加入 JDK 17 支持**的版本，官方配套写的是 Hadoop 3.4.1 / Tez 0.10.5；Hive 4.0.1 才明确配套 Hadoop 3.3.6。所以「4.1.0 + 3.3.6」不在官方测试矩阵内，素材自己也用 HIVE-28683 做兼容。另一头，4.2.0（2025-11-23）起**最低要求 JDK 21**，意味着 JDK 17 这条线实际停在 4.1.x。

## 安装九步

1. 前置：JDK / Hadoop / MySQL 都要先能跑。
2. 解压到 `/opt/soft/`，改名 `hive-4.1.0`。
3. `HIVE_HOME` + `PATH` 进 `/etc/profile` 或 `~/.bashrc`。
4. 在 HDFS 建数仓目录：`hdfs dfs -mkdir -p /hive/warehouse`、`chmod 777`。
5. `$HIVE_HOME/conf` 下由模板生成 `hive-site.xml`（素材随后要求清空重写，见勘误）。
6. `mysql-connector-java-8.0.33.jar` 拷进 `$HIVE_HOME/lib/`。
7. 对齐 Guava：删 `hive/lib/guava-*.jar`，拷 `$HADOOP_HOME/share/hadoop/common/lib/guava-*-jre.jar`。
8. `schematool -dbType mysql -initSchema`，成功标志 `schemaTool completed`。
9. 启动顺序：Hadoop → MySQL → `hive --service metastore` → `hive --service hiveserver2` → `hive` CLI。

## `hive-site.xml` 的六类关键项

| 类别 | 键 | 值 |
|---|---|---|
| 数仓目录 | `hive.metastore.warehouse.dir` | `/hive/warehouse` |
| Metastore 服务 | `hive.metastore.uris` | `thrift://localhost:9083` |
| 元数据库连接 | `javax.jdo.option.ConnectionURL` | `jdbc:mysql://127.0.0.1:3306/hive?createDatabaseIfNotExist=true&useSSL=false&serverTimezone=Asia/Shanghai` |
| 驱动 / 账号 | `ConnectionDriverName` / `UserName` / `Password` | `com.mysql.cj.jdbc.Driver` / `root` / 实际密码 |
| 执行引擎 | `hive.execution.engine` | `mr` |
| HiveServer2 | `hive.server2.thrift.port` / `bind.host` / `authentication` | `10000` / `0.0.0.0` / `NONE` |
| CLI 显示 | `hive.cli.print.current.db` / `print.header` | `true` |

- `createDatabaseIfNotExist=true` 让首次连接自动建 `hive` 库；`useSSL=false` + 指定时区是 MySQL 8.0 驱动常见的两个必填项。
- HiveServer2 的 `bind.host=0.0.0.0` 是给 [[Apache Zeppelin]] 这类远程客户端用的。

## 三个反复被踩的点

- **Guava 冲突 → `NoSuchMethodError`**：Hive 与 Hadoop 各带一份 Guava，版本不一致就在运行时炸。
- **schema 已存在**：先 `DROP DATABASE IF EXISTS hive; CREATE DATABASE hive CHARACTER SET utf8mb4;` 再重跑 `schematool`。
- **JDBC 驱动没进 `lib/` → `NoClassDefFoundError`**：`schematool` 与 CLI 都要用到它。

## 素材勘误与不一致

1. **`hive.server2.active.passive.ha.enable=true` 的注释写「免去检查」**。该键是 HiveServer2 **主备 HA 开关**（需要 ZooKeeper 参与选主），单机环境置 `true` 不会「免检查」，只会把 HiveServer2 拉进 HA 分支；素材全文没有 ZK 与 HA 配置。**判定证据**：① 键名语义即 active/passive HA；② 素材其他 HiveServer2 键（`authentication=NONE`、`bind.host=0.0.0.0`）都是单机写法，与本键语义冲突。状态：已裁定（配置语义错误，单机应保持默认 `false`）。
2. **`cp hive-default.xml.template hive-site.xml` 之后立刻「清空原内容」**：模板拷贝无意义，直接新建文件即可。状态：已裁定（冗余步骤，非事实错误）。
3. **下载地址写成 shell 命令**：`https://hive.apache.org/general/downloads/` 放在 ```shell 块里，直接执行会报错，应 `wget` 或浏览器下载。状态：已裁定。
4. **参考资源标注混乱**：HIVE-28683 被标成「Hive4 与低版本 Hadoop 安装指南」并带 `[reference:12]` 残留，与实际 JIRA 标题不一致，需人工核对。状态：待人类确认。

> ⚠️ 矛盾：与 [[2026-10-27-CentOS7安装MySQL]] 冲突——本篇要求 MySQL 8.0（`com.mysql.cj.jdbc.Driver`、`serverTimezone`），那一篇只覆盖 MySQL 5.6/5.7，待人类裁决实际装哪个版本。
