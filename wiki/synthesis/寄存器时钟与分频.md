寄存器在软件视角里是「CPU 里的一块存储」，在硬件视角里就是一组触发器；两者被同一个时钟驱动。本页把微机原理的寄存器/标志/位运算，与 FPGA 的 reg/wire/always 对应起来，说明「写程序」和「描述电路」差在哪。

## 两侧的词汇表

**微机原理侧**（3 篇素材）：

- [[80x86寄存器]]：8 个通用寄存器（AX/BX/CX/DX 与 SI/DI/BP/SP）、4 个段寄存器、IP、FLAGS。
- [[标志寄存器]]：CF/PF/AF/ZF/SF/OF 六个状态位 + TF/IF/DF 三个控制位。
- [[小端存储]]与[[字长]]：多字节在内存里低字节在前；8086 的字长是 16 位。
- [[物理地址计算]]：段基址 ×16 + 偏移 = 20 位地址。
- [[位运算]]：掩码、置位、翻转、检测四种套路。

**FPGA 侧**（1 篇素材）：

- [[Verilog模块]]：`module ... endmodule` 描述一个电路单元，端口分 input/output。
- [[wire与reg]]：`wire` 是连线（组合逻辑的输出），`reg` 是存储（时序逻辑的状态）。
- [[阻塞与非阻塞赋值]]：`=` 立即生效（组合），`<=` 在时钟沿统一更新（时序）。
- [[引脚约束与位流]]：逻辑设计要映射到具体引脚，再生成位流烧进板子。

## 对应关系

| 软件的讲法 | 硬件的讲法 |
|---|---|
| 寄存器 AX 保存一个 16 位数 | `reg [15:0] ax;`（16 个触发器并联） |
| 指令 `add ax, bx` | 一个加法器 + 在时钟沿把结果写回 `ax` |
| 程序计数器 IP 指向下一条指令 | 一个每个时钟 `+1` 的计数器，或由跳转逻辑改写 |
| 条件跳转 `jz` | 组合逻辑根据 ZF 算出计数器的下一个值 |
| FLAGS 记录运算结果 | 一组与运算结果同拍的比较寄存器 |
| 访问内存 | 地址总线输出 + 读/写控制信号 |
| 程序按顺序一条条执行 | 所有 `always` 块在每个时钟沿同时动作 |

## 三个真正的差别

### 1. 顺序 vs 并行

CPU 是「取指—译码—执行」一条流水线，任一时刻只有一个动作在主导；FPGA 的多个 `always` 块是**同时**运行的，写代码时若把它们当成顺序语句来推理，就会出现「为什么两个块读到的是旧值」这类问题。[[阻塞与非阻塞赋值]] 那一页讲的就是平行语义下的赋值顺序。

### 2. 时钟是显式的

软件里时间由指令条数隐含；硬件里时间由时钟沿显式给出，`always @(posedge clk)` 里的语句只在上升沿生效。一个 `always` 块里写了多少行，只要综合得下，都是一个周期完成——「几行代码 = 几个周期」在硬件里不成立。

### 3. 复位是必须的

CPU 上电由复位向量决定从哪开始执行；FPGA 上电时 `reg` 的值不确定，必须显式写复位（`if (!rst_n)`）或给初值，否则第一位状态是随机的。

## 分频：两种视角的同一个东西

素材里点灯的例子用计数器把系统时钟分频：计数到某个值翻转一次 LED，周期就是「计数值 × 2 × 时钟周期」。

- 硬件视角：这是一个模 N 计数器 + 一位翻转寄存器，最朴素的定时器。
- 微机视角：8086 系统里的定时由 8253/8254 可编程定时器完成，本质也是「对输入时钟计数，到数触发」。

两条线的差别只在「计数上限是写死还是可编程」。理解了这一点，`delay()` 之类的忙等函数在硬件里为何不可用也就清楚了——硬件没有「什么都不做地等」，只有计数器。

## 素材未覆盖

- 中断（8086 的 IF 位与 FPGA 的中断控制器）只有标志位定义，没有例子。
- 流水线、总线时序、DMA 全库无素材。
- FPGA 侧缺状态机（FSM）素材，而状态机才是把「程序逻辑」映射到硬件的主要手段。
