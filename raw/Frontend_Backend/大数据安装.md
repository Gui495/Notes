## 一、分布式基础概念

- **分布式系统**：由分布在不同主机上的进程协同工作，共同构成完整应用系统。
- **Browser/Web Server** 属于典型的瘦客户端架构。

## 二、大数据 4V 核心特征

| 特征                    | 说明                                             |
| :---------------------- | :----------------------------------------------- |
| **Volume（海量性）**    | 数据体量庞大，达到 TB/PB 级别                    |
| **Velocity（高速性）**  | 数据产生和处理速度快，流式实时场景居多           |
| **Variety（多样性）**   | 数据格式丰富，包含结构化、半结构化、非结构化数据 |
| **Value（低价值密度）** | 海量原始数据中有效信息占比低，需深度挖掘提取价值 |

## 三、Hadoop 概述

Hadoop 是开源、高可靠、可横向扩展的分布式大数据计算框架。

- **核心能力**：依托 MapReduce 编程模型处理集群中的超大规模数据集。
- **扩展能力**：可从单台服务器平滑扩容至数千节点，每台节点同时承担 **存储 + 计算** 角色。

### Hadoop 四大核心模块（架构图）

![deepseek_mermaid_20260802_89a21a](C:\Users\Administrator\Downloads\deepseek_mermaid_20260802_89a21a.png)



- **hadoop-common**：提供通用 I/O、工具、配置等基础能力。
- **HDFS**：分布式文件系统，负责海量数据的持久化存储。
- **YARN**：资源调度与作业管理框架，统一管理集群 CPU、内存资源。
- **MapReduce**：基于 YARN 运行的分布式并行计算引擎，面向大规模离线数据处理。

### MapReduce 运行原理（流程图）

![deepseek_mermaid_20260802_07d4e1](C:\Users\Administrator\Downloads\deepseek_mermaid_20260802_07d4e1.png)



**详细步骤**：

1. 原始大数据文件被切分成多个分片，分发至多个 `MapTask` 并行执行。
2. 每个 `MapTask` 输出键值对，经过**分区（Partition）**、**排序（Sort）**、**分组（Group）** 后，将相同 Key 的数据发送给同一个 `ReduceTask`。
3. `ReduceTask` 聚合相同 Key 的数据，汇总输出最终计算结果。

## 六、全局环境变量配置（`/etc/profile`）

```shell
# ==================== JDK17 环境 ====================
export JAVA_HOME=/opt/soft/jdk17012
export PATH=$JAVA_HOME/bin:$PATH
# JDK17 JPMS 模块化反射放行参数（解决 Hadoop/HBase 底层反射报错）
export HADOOP_OPTS="--add-opens java.base/java.lang=ALL-UNNAMED \
                    --add-opens java.base/java.io=ALL-UNNAMED \
                    --add-opens java.management/com.sun.jmx.mbeanserver=ALL-UNNAMED \
                    --add-opens java.base/sun.nio.ch=ALL-UNNAMED"

# ==================== Hadoop 全局变量 ====================
export HADOOP_HOME=/opt/soft/hadoop-3.3.6
export HADOOP_MAPRED_HOME=$HADOOP_HOME
export HADOOP_COMMON_HOME=$HADOOP_HOME
export HADOOP_HDFS_HOME=$HADOOP_HOME
export YARN_HOME=$HADOOP_HOME
export HADOOP_COMMON_LIB_NATIVE_DIR=$HADOOP_HOME/lib/native
export PATH=$PATH:$HADOOP_HOME/sbin:$HADOOP_HOME/bin
export HADOOP_INSTALL=$HADOOP_HOME
export HADOOP_CONF_DIR=$HADOOP_HOME/etc/hadoop

# ==================== ZooKeeper 环境 ====================
export ZOOKEEPER_HOME=/opt/soft/apache-zookeeper-3.8.4-bin
export PATH=$PATH:$ZOOKEEPER_HOME/bin

# ==================== HBase 环境（复用 Hadoop JVM 参数） ====================
export HBASE_HOME=/opt/soft/hbase-2.6.0-bin
export HBASE_OPTS="$HADOOP_OPTS"
export PATH=$PATH:$HBASE_HOME/bin
```



**使配置生效**：`source /etc/profile`

## 七、Hadoop 运行模式

1. **Standalone（单机本地模式）**
   - 无后台守护进程，全部程序运行在同一 JVM，适合单元测试和调试。
2. **Pseudo‑distributed（伪分布式模式）**
   - 单台机器模拟完整集群，同时启动 NameNode、DataNode、ResourceManager 等所有进程，是学习和测试的首选模式。

## 八、Hadoop 核心配置文件

所有配置文件位于 `${HADOOP_HOME}/etc/hadoop/*.xml`。

### 1. `core-site.xml` — 全局核心配置

```xml
<configuration>
    <!-- 默认 HDFS 通信地址与端口（可使用主机名或 IP） -->
    <property>
        <name>fs.defaultFS</name>
        <value>hdfs://192.168.220.129:9000</value>
    </property>
    <!-- Hadoop 临时数据存储目录 -->
    <property>
        <name>hadoop.tmp.dir</name>
        <value>/opt/soft/hadoop-3.3.6/tmp</value>
    </property>
</configuration>
```



### 2. `hdfs-site.xml` — HDFS 存储配置

```xml
<configuration>
    <!-- 数据副本数：伪分布式仅 1 台节点，设为 1；生产集群默认为 3 -->
    <property>
        <name>dfs.replication</name>
        <value>1</value>
    </property>
</configuration>
```



### 3. `mapred-site.xml` — MapReduce 计算框架

```xml
<configuration>
    <!-- 指定 MapReduce 任务运行在 YARN 上 -->
    <property>
        <name>mapreduce.framework.name</name>
        <value>yarn</value>
    </property>
</configuration>
```



### 4. `yarn-site.xml` — YARN 资源调度配置

```xml
<configuration>
    <!-- ResourceManager 绑定的主机名（伪分布式可用 localhost） -->
    <property>
        <name>yarn.resourcemanager.hostname</name>
        <value>localhost</value>
    </property>
    <!-- NodeManager 开启 MapReduce 数据洗牌服务 -->
    <property>
        <name>yarn.nodemanager.aux-services</name>
        <value>mapreduce_shuffle</value>
    </property>
</configuration>
```

### 5. hadoop-env.sh -  启动环境配置

```shell
# 指定各服务以 root 身份运行（适用于学习测试环境）
export HDFS_NAMENODE_USER=root
export HDFS_DATANODE_USER=root
export HDFS_SECONDARYNAMENODE_USER=root
export YARN_RESOURCEMANAGER_USER=root
export YARN_NODEMANAGER_USER=root

# 强烈建议在此处也显式指定 JAVA_HOME，防止系统找不到 JDK
export JAVA_HOME=/opt/soft/jdk17012

# JDK17 反射放行参数（配合你之前 /etc/profile 里的配置）
export HADOOP_OPTS="--add-opens java.base/java.lang=ALL-UNNAMED --add-opens java.base/java.io=ALL-UNNAMED --add-opens java.management/com.sun.jmx.mbeanserver=ALL-UNNAMED --add-opens java.base/sun.nio.ch=ALL-UNNAMED"
```

## 九、SSH 免密登录配置（集群启停必备）

**作用**：集群启停脚本需要远程连接各节点，免密 SSH 可省去重复输入密码。

**操作步骤**（伪分布式仅需本机互通）：

1. **生成无密码 RSA 密钥对**（在主节点执行）：

   

   ```bash
   ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa
   ```

   

2. **将公钥追加到授权文件**：

   - 伪分布式（单机自连通）：

     ```bash
     cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
     ```

     

   - 完全分布式（多从节点）：

     ```bash
     # 拷贝公钥到从节点
     scp ~/.ssh/id_rsa.pub root@slave主机名:~/tmp.pub
     # 在从节点追加至授权列表
     cat ~/tmp.pub >> ~/.ssh/authorized_keys
     ```

     

3. **收紧文件权限**（SSH 强制校验）：

   ```shell
   chmod 600 ~/.ssh/authorized_keys
   ```

## 十、Hadoop 初始化与集群启停

1. **格式化 HDFS**（**仅首次安装执行一次**，重复格式化会丢失所有数据）：

   ```shell
   hdfs namenode -format
   ```

   

2. **集群启停脚本**（位于 `$HADOOP_HOME/sbin`）：

   bash

   ```shell
   # 一键启动 HDFS + YARN（Hadoop 3.x 仍保留，但官方推荐分别启动）
   start-all.sh
   
   # 分别启动
   start-dfs.sh
   start-yarn.sh
   
   # 停止集群
   stop-all.sh
   ```

   

3. **指定自定义配置目录启动**：

   ```shell
   start-all.sh --config /自定义配置文件夹绝对路径
   ```

   

   或通过全局环境变量指定：

   ```shell
   export HADOOP_CONF_DIR=/自定义配置文件夹路径
   ```

## 十一、宿主机访问 WebUI 页面配置

修改虚拟机内 `/etc/hosts`：

1. 添加 IP 与主机名映射（**确保与 `core-site.xml` 中的地址一致**）：

   ```bash
   192.168.220.129 master
   192.168.220.129 hd01
   ```

   

同时，**宿主机也需要配置 hosts**，将虚拟机 IP 映射为对应的主机名（如 `master`），以便浏览器通过主机名访问 WebUI。

Hadoop 3.x 默认端口如下：

| 服务                       | Web UI 端口 | 访问地址                            |
| :------------------------- | :---------- | :---------------------------------- |
| **HDFS NameNode**          | 9870        | `http://master:9870`                |
| **HDFS SecondaryNameNode** | 9868        | `http://master:9868`（可选）        |
| **YARN ResourceManager**   | 8088        | `http://master:8088`                |
| **JobHistory Server**      | 19888       | `http://master:19888`（需单独启动） |

### 示例 1：HDFS 文件下载到本地

java

```java
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IOUtils;

import java.io.FileOutputStream;
import java.io.InputStream;
import java.io.OutputStream;
import java.net.URI;

public class HdfsDownload {
    public static void main(String[] args) throws Exception {
        // 注意：若未指定用户，可能使用当前系统用户，建议统一指定
        FileSystem fs = FileSystem.get(new URI("hdfs://192.168.220.129:9000"), new Configuration(), "root");
        InputStream in = fs.open(new Path("/hadoop/LICENSE.txt"));
        OutputStream out = new FileOutputStream("F://hadoop/LICENSE.txt");
        IOUtils.copyBytes(in, out, 4096, true);
    }
}
```



### 示例 2：删除 HDFS 文件

java

```java
import org.apache.hadoop.conf.Configuration;
```

### 实例4：上传文件

```java
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.Path;
import java.net.URI;

public class HdfsUploadSimple {
    public static void main(String[] args) throws Exception {

```

## 十五、常见问题与注意事项

| 问题现象                          | 可能原因与解决方案                                           |
| :-------------------------------- | :----------------------------------------------------------- |
| **HDFS 启动后 DataNode 未启动**   | 检查 `hadoop.tmp.dir` 目录权限，或多次格式化导致 clusterID 不一致，需清空 tmp 目录后重新格式化。 |
| **Java API 连接 HDFS 报权限错误** | 指定正确的用户（如 `"root"`）或配置 HDFS 权限为 false（`dfs.permissions.enabled=false`）。 |
| **WebUI 无法访问**                | 检查防火墙是否开放端口（HDFS：9870，YARN：8088）；宿主机的 hosts 文件需正确解析虚拟机主机名。 |
| **JDK17 反射警告**                | 已通过 `HADOOP_OPTS` 添加 `--add-opens`，若仍有其他模块报错，可参照日志补充相应 opens 参数。 |
| **ZooKeeper 启动失败**            | 检查 `dataDir` 目录是否存在且可写，并确认 `clientPort` 未被占用。 |
